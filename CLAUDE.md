This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Personal portfolio for Venkataramana Hegde: a static site built with pnpm, Next.js 16 (App Router, Turbopack, `cacheComponents`), React 19, Tailwind CSS v4 and TypeScript. There is no test suite.

## Commands

```bash
pnpm dev         # dev server on :3000 (security headers are off in dev)
pnpm build       # production build; every route must stay ○ Static
pnpm start       # serve the build; use this to check CSP and headers
pnpm lint        # ESLint (eslint-config-next)
pnpm themes:check       # contrast gate over every theme; fails on one that is not legible
pnpm exec tsc --noEmit  # types; LayoutProps comes from route types generated by dev/build
```

## Next.js 16 caveat

AGENTS.md applies: APIs differ from older Next.js. Read `node_modules/next/dist/docs/` before using an unfamiliar API. Under `cacheComponents`, avoid request-time values such as `new Date()` in server components, because the page must prerender. That is why the footer year is a literal.

## Architecture

The site is a **code editor you can operate**. Every panel does real work; none of it is decoration.

- **Content is data.** `src/content/profile.ts` holds every fact: person, experience, projects, skills (as `extensions`), education, certifications, stats. `src/content/workspace.ts` turns routes into a file tree (name, folder, language, short `cmd`, title, blurb) and drives the explorer, the tab bar, the terminal and the command palette. `src/content/search.ts` builds the search index from both. Facts change in `profile.ts`; routes change in `workspace.ts`.
- **Routes are files.** `/` is `_hello.tsx`, `/about` is `_about-me.md`, `/experience` is `_experience.log`, `/projects` is `_projects.json`, `/contact` is `_contact-me.ts`, and each project is `src/projects/<slug>.tsx`. `navFiles` (ordered by `NAV_ORDER`) are pinned tabs that cannot be closed, so the tab row is the site navigation.
- **Shell.** `components/ide/Shell.tsx` lays out title bar, activity bar, side panel, tabs, editor, terminal and status bar. `ide-state.tsx` holds all shell state and the keyboard shortcuts (Ctrl+K palette, Ctrl+` terminal, Ctrl+B side panel, Ctrl+Shift+E explorer). It uses `useSyncExternalStore` for the desktop media query so the terminal can default open on desktop and closed on phones without a hydration mismatch — do not replace that with `useEffect` + `setState`, which the React Compiler rejects.
- **The panels carry real content.** Explorer navigates. Search searches every indexed line. Source control renders `experience` as commits with file-level diffstats and achievements as added lines. Extensions renders `extensions` as a marketplace, where the numbers (`since`, `projects`, `level`) are honest rather than invented download counts.
- **Terminal.** `Terminal.tsx` runs real commands (`help`, `ls`, `open <file>`, `projects`, `skills`, `git log`, `neofetch`, …), with Tab completion and ↑ history. Output can contain clickable file links that route. New commands go in the `switch` and in `COMMANDS` for completion.
- **Contact form.** Writes a live `message.ts` preview as you type. The site is static, so submitting opens the visitor's own mail client with the body prefilled — never claim a message was sent from the page.
- **Themes are installable.** `src/content/themes.ts` is the single source of truth for every colour: 13 themes, dark and light, default **VS Code Dark Modern**. UI tokens (`bg`, `panel`, `rail`, `raise`, `line`, `fg`, `muted`, `faint`, `amber`, `mint`, ...) are kept separate from the `--syn-*` syntax family, because real editor themes do not reuse chrome colours for code; a theme that omits `syntax` inherits the UI tokens. `globals.css` holds the **default** theme as literal `:root` values so first paint needs no JavaScript, and `Bootstrap.tsx` serialises the others and applies the visitor's choice before paint -- so changing `defaultThemeId` means changing those `:root` literals too. `src/theme.ts` derives from the default for `next/og` and the theme-color meta. Themes install, uninstall and persist per browser; `pnpm themes:check` gates all of them on contrast.
- **Settings and keybindings are real.** `src/content/settings.ts` and `src/content/keybindings.ts` define them; `/settings` renders `settings.json` and `keybindings.json` as editable files, and the keydown handler reads the keybinding table, so documented shortcuts cannot drift from the real ones. Numbers apply as custom properties, booleans and enums as `data-*` on `<html>`. **Only ship a setting whose effect already exists** -- a switch that flips nothing is the same lie as an invented count.
- **Security headers.** In `next.config.ts`, production only. A strict CSP (`'self'`) covers every path except `*.pdf`.
- **Gitlantis.** `/gitlantis` is a port of the Gitlantis VS Code extension (Brian Njogu, Apache-2.0): same GLB boat, lighthouse and buoy models, three.js `Water` and `Sky`, boat physics, camera rig, minimap, compass and ocean/horn audio. `components/ide/gitlantis/engine.ts` is plain three.js; `Gitlantis.tsx` is the HUD. Folders and files come from `workspace.ts`. Assets live in `public/gitlantis/` (see its NOTICE.txt); `boat.glb` was decompressed from Draco so no worker or WASM is needed under the CSP, and `connect-src` allows `blob:` for embedded textures. Audio only starts after the visitor presses Start.
- **Pets.** The bottom panel has Terminal and Pets tabs (`BottomTabs.tsx`; `bottomTab` and `openPets` live in `ide-state`). `components/ide/pets/` ports VS Code Pets (Anthony Shaw, MIT; dog sprites CC BY-ND, used unmodified): `data.ts` is the sprite and scene catalogue, `engine.ts` runs wandering, petting and ball-chasing outside React, `PetsPanel.tsx` is the UI. Assets are in `public/pets/` (see NOTICE.txt). Pets and scene persist in localStorage; the `pets` terminal command and palette entry open the tab.
- **Static assets.** `public/venkataramana-hegde-resume.pdf`, and project screenshots in `public/projects/` captured at 1440×900 from the live sites.

## Design rules

The owner chose this direction from two references: a Behance "Portfolio Concept V.2" (navy, underscore tab names, live code panel in the contact form) and a VS-Code-themed portfolio. Keep these unless the owner says otherwise.

- Fonts follow VS Code: a system UI font for the chrome, Consolas/Menlo for file contents. `editor.fontFamily` switches everything back to Fira Code, which is how the site shipped before the owner asked for the VS Code look.
- One accent only. `--amber` is the accent **token**, not literally amber -- under the default theme it is VS Code's link blue -- and it marks the active state and primary actions, nothing else. `--mint` marks live or positive signals. Nothing is coloured for decoration.
- The chrome must stay honest: if a panel looks like it does something, it does it. No fake badges, no invented counts, no error/warning numbers that are not real.
- Keep it user-friendly: the five main tabs are always visible, the terminal announces what to type, and every panel has an empty state that says what it is for.
- Accessibility: visible focus rings, `aria-pressed` on toggles, `aria-current` on the open file, every new-tab link carries an sr-only notice, and the terminal log is an `aria-live` region.
- Do not publish the phone number on the site. The résumé PDF is the only place it appears.
- Do not claim availability or job-seeking on the site unless the owner says so.
